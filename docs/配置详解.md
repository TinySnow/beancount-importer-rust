# 配置详解

本文档覆盖所有配置字段、规则语义、账户回退逻辑。需要看场景决策和完整样例，见[配置最佳实践指南](./配置最佳实践指南.md)。

## 1. 配置加载顺序

1. `--global-config` → 否则 `config/global.yml`
2. `--config` → 否则 `config/<banks|third_party|securities>/<provider>.yml` → 否则 `global.yml` 中的 `providers.<provider>`
3. `mapping_file` → 否则 `mapping/<category>/<provider>.yml` → 否则内嵌映射

补充规则：
- provider 配置覆盖 global 默认值；未设定的字段回退 global
- `mapping_file` 相对路径优先按 provider 配置文件目录解析，其次按当前工作目录
- 内嵌 mapping 仅覆盖内置供应商

## 2. provider 结构

```yaml
name: "wechat"
mapping_file: "mapping/third_party/wechat.yml"

default:
  asset_account: "Assets:Wallet:WeChat:Balance"
  expense_account: "Expenses:Unknown"
  income_account: "Income:Unknown"
  currency: "CNY"

# 证券专用（可选）
securities_accounts:
  cash_account: "Assets:Broker:Galaxy:Cash"
  fee_account: "Expenses:Broker:Fee"            # 省略时回退 default.expense_account
  pnl_account: "Income:Broker:PnL"              # 省略时回退 default.income_account
  rounding_account: "Expenses:Broker:Rounding"  # 省略时推导自 fee_account
  repo_interest_account: "Income:Investing:Interest"
inventory_seed_files: []  # 历史 .bean 文件，跨账期 lot 预加载
inventory_seed_exclude_dirs: ["tmp"]  # 目录扫描时跳过的目录名（默认 ["tmp"]，用 [] 关闭）

tabular_options:
  delimiter: ","
  quote: '"'
  flexible: true
  encoding: "auto"

skip_header_lines: 0
has_header_row: true

output:
  date_format: "%Y-%m-%d"
  decimal_places: 2
  emit_open_directives: false
  booking_method: "FIFO"        # 可选，lot 匹配方法

rules: []
```

关键要点：
- `inventory_seed_files`：相对路径按 provider 配置目录解析，用于跨账期导入时预加载历史 lot
- `inventory_seed_exclude_dirs`：目录扫描时跳过的目录名列表（大小写不敏感），默认 `["tmp"]` 用于排除 batch 输出暂存目录
- 证券最小必填 4 项：`default.asset_account`、`securities_accounts.cash_account`、`default.expense_account`、`default.income_account`。`fee/pnl/rounding` 未配时自动回退（见 §5）
- 旧平铺字段（`default_cash_account` 等）已移除

## 3. tabular_options

| 字段 | 默认值 | 说明 |
|------|--------|------|
| `delimiter` | `,` | 分隔符 |
| `quote` | `"` | 引号字符 |
| `flexible` | `false` | 允许行列不齐 |
| `encoding` | `auto` | `UTF-8`/`GBK`/`auto` |
| `comment` | — | 注释行前缀 |

`flexible` 与 `--strict` 的交互：`flexible=false` 时列数异常直接报错；`flexible=true` 时非 strict 下跳过坏行并记 warning，strict 下仍失败。

Excel 导出字面值自动清洗：`="0"` → `0`、`="240599141221"` → `240599141221`（仅处理 `="..."` 格式）。

## 4. output

| 字段 | 说明 |
|------|------|
| `date_format` | 交易日期输出格式 |
| `decimal_places` | 金额小数位 |
| `emit_open_directives` | 是否输出 `open` 指令 |
| `open_date` | `open` 日期，不填用最早交易日 |
| `booking_method` | lot 匹配方法（如 `"FIFO"`） |

writer 自动输出 `commodity`、metadata 按 key 排序、优先使用本次导入内的买入持仓做 lot 拆分。

## 5. 规则系统

### 5.1 定义

```yaml
- name: "餐饮支出"
  conditions:
    - field: "type"
      equals: "支出"
    - field: "item"
      regex: "(咖啡|奶茶|外卖)"
  action:
    debit_account: "Expenses:Food"
    credit_account: "Assets:Wallet:WeChat:Balance"
    metadata: { scene: "daily" }
    tags: ["food"]
  priority: 10
  terminal: false
```

### 5.2 运算符

| 运算符 | 写法 | 语义 |
|--------|------|------|
| `equals` | `equals: "支出"` | 完全相等 |
| `contains` | `contains: "交通"` | 包含子串 |
| `regex` | `regex: "咖啡\|奶茶"` | 正则命中 |
| `starts_with` | `starts_with: "银行卡"` | 前缀匹配 |
| `ends_with` | `ends_with: "-TEST"` | 后缀匹配 |
| `in` | `in: ["A", "B"]` | 等于列表中任一项 |
| `not_empty` | `not_empty:` | 字段存在且非空 |
| `is_empty` | `is_empty:` | 字段为空或不存在 |
| `greater_than` | `greater_than: 100` | 数值大于阈值 |
| `less_than` | `less_than: 100` | 数值小于阈值 |
| `between` | `between: { min: 50, max: 200 }` | 闭区间 |

### 5.3 执行顺序

`global_rules` → provider `rules` → 各自内部 `priority` 升序 → 条件数升序 → 文件顺序。结论：**后执行规则覆盖先执行结果**。

### 5.4 多规则命中合并

- 单值字段（账户、payee、narration）：**后命中覆盖先命中**
- `metadata`：按 key 合并，后命中覆盖同 key
- `tags/links`：追加，**不去重**
- `ignore`：一旦为 `true` 保持 `true`

### 5.5 分层规则策略（减少规则数）

传统 N 种消费 × M 种支付方式 = N×M 条规则。分层写法只需 N+M 条：

```yaml
# Layer 1: 付款方式 → 贷方 (priority 100)
- name: "付款-余额"
  conditions: [{ field: "method", contains: "余额" }]
  action: { credit_account: "Assets:Wallet:Alipay:Balance" }
  priority: 100

# Layer 2: 消费类别 → 借方 (priority 10-20)
- name: "消费-餐饮"
  conditions: [{ field: "category", equals: "餐饮美食" }]
  action: { debit_account: "Expenses:Food" }
  priority: 10
```

Layer 2 只设 `debit_account`，`credit_account` 由 Layer 1 提供。两条规则各命中一半，合并后得到完整分录。

### 5.6 跨字段 OR 语法

不写 `match_mode: or`，用 `fields` 数组实现跨字段正则匹配：

```yaml
- conditions:
    - fields: [peer, item]
      regex: 小吃|零食|火锅|串串|餐饮|中餐
```

等价于 `peer 匹配 OR item 匹配`，一条规则覆盖两个字段。

### 5.7 terminal / ignore / flag

- `terminal: true`：命中后停止后续规则
- `ignore: true`：该条记录最终不输出
- `flag: "*"`：完成标记

### 5.8 常见误区

- **`not_empty` 写成 `not_empty: true`** → 正写：`not_empty:`
- **以为 priority 越大越早** → 实际：越大越晚执行
- **以为 tags/links 去重** → 实际：仅追加
- **单条规则里写括号嵌套** → 不支持，拆成多条或用 `in`/`regex`
- **旧配置路径 `/config/`** → 新路径 `config/`（已无斜杠开头）

## 6. mapping 配置

```yaml
date: "交易时间"
payee: "交易对方"
narration: "商品"
amount:
  column: "金额(元)"
  transform: abs                  # 可选 abs / negate

extra_fields:
  peer: "交易对方"
  orderId: "交易单号"
  txType: "交易类型"
  method: "支付方式"

date_formats:
  - "%Y-%m-%d %H:%M:%S"
  - "%Y/%m/%d %H:%M"
```

### 6.1 详写格式（可选）

```yaml
payee:
  column: "交易对方"
  default: "匿名对手"
  transform: null
  regex_extract: "^(.*?)(\\(|$)"
```

- `column`：来源列名
- `default`：字段为空时的默认值
- `transform`：`abs`/`negate`（数值字段）
- `regex_extract`：正则提取，优先返回第 1 捕获组

### 6.2 其他 mapping 规则

- `extra_fields` 兼容旧 `csv_column -> metadata_key` 格式
- XLSX 输入时 reader 自动按列名匹配得分选择表头行
- metadata key 输出前自动归一化（中→英、非法→哈希）

### 6.4 收入/支出分列银行账单

银行账单通常收入金额和支出金额在不同列（非单一金额列）。映射时：

```yaml
income_amount: { column: "收入金额", transform: abs }
expense_amount: { column: "支出金额", transform: abs }
```

工具自动合并为单一 `amount` 字段（收入为正，支出为负）。

## 7. 账户回退优先级

### 7.1 现金流

**支出借方：** `rules[].debit_account` → `default.expense_account` → `Expenses:Unknown`

**支出贷方：** `rules[].credit_account` → `default.asset_account` → 内置兜底

**收入贷方：** `rules[].credit_account` → `default.income_account` → `Income:Unknown`

### 7.2 证券（完整回退链）

**券商现金账户：** `rules[].debit/credit_account` → `securities_accounts.cash_account` → 从 `default.asset_account` 推导（`:Securities → :Cash`）→ `Assets:Broker:Cash`

**fee_account：** `rules[].fee_account` → `securities_accounts.fee_account` → `default.expense_account` → `Expenses:Investing:Fees`

**pnl_account：** `rules[].pnl_account` → `securities_accounts.pnl_account` → `default.income_account` → `Income:Investing:Capital-Gains`

**rounding_account：** `rules[].rounding_account` → `securities_accounts.rounding_account` → 从 fee_account 推导 → `Expenses:Investing:Rounding`

**repo_interest_account：** `securities_accounts.repo_interest_account` → `Income:Investing:Interest`

### 7.3 证券场景速查

| 场景 | 持仓变动 | 现金变动 | 差额去向 |
|------|---------|---------|---------|
| 普通买入 | 持仓增加 | 现金减少 | >0→fee, <0→rounding |
| 普通卖出 | 持仓减少 | 现金增加 | >0→pnl, 差额→fee/rounding |
| 逆回购买入 | 持仓增加(面值100/份) | 现金减少 | 差额→fee/rounding |
| 逆回购到期 | 持仓减少 | 现金+利息入账 | 正差额→利息收入 |
| 银证转账 | — | 现金变动 | 仅资产间划转，不涉及 pnl |

## 8. 严格模式 (`--strict`)

解析阶段列数异常、转换失败均立即退出。默认（非 strict）下坏行跳过并继续。

## 9. 日志故障排查

| 日志内容 | 可能原因 | 检查 |
|---------|---------|------|
| `Failed to parse` | 文件编码/格式异常 | 文件是否损坏，encoding 是否匹配 |
| `No field mapping found` | mapping 路径错误 | mapping 文件是否存在、路径是否正确 |
| `Invalid budgets YAML` | YAML 语法错误 | 缩进是否一致，逗号是否缺失 |
| `Unknown provider` | provider 名拼写错误 | `-p` 参数是否与注册名一致 |
| `...records parsed` 之后无输出 | 所有记录均被规则忽略 | 检查 ignore 规则、mapping 字段映射 |
| `Transformation complete: X success / Y ignored / Z failed` | 存在失败或忽略记录 | 非 strict 下 Y/Z 不为 0 需人工检查 |

调试命令：
```bash
cargo run -- -p alipay -s data.csv -c config.yml --log-level info
```

## 10. 附录

### 10.1 旧→新字段迁移

| 旧字段或写法 | 新写法 |
|------------|--------|
| `/config/provider.yml` | `config/provider.yml` |
| `default_asset_account` | `default.asset_account` |
| `default_cash_account` | `securities_accounts.cash_account` |
| `default_fee_account` | `securities_accounts.fee_account` |

### 10.2 strict × flexible 组合

| flexible | strict | 行为 |
|----------|--------|------|
| false | — | 列数异常立即报错 |
| true | false | 跳过坏行，继续 |
| true | true | 列数异常仍报错 |
