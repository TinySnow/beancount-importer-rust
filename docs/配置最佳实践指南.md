# 配置最佳实践指南

从零开始写配置的推荐流程，不含重复的字段语义（详见[配置详解](./配置详解.md)）。

## 1. 选场景

**你手上的账单是哪种？**

| 场景 | 特征 | 需要的文件 |
|------|------|----------|
| A. 银行 / 第三方支付 | CSV，消费+收入流水 | `provider.yml` + `mapping.yml` |
| B. 证券（券商） | XLSX/CSV，有买卖持仓 | A 全部 + `securities_accounts` |

## 2. 最小可用配置

### 场景 A：现金流

```yaml
# config/alipay.yml
name: alipay
mapping_file: mapping/third_party/alipay.yml

default:
  asset_account: Assets:Digital:Alipay:Balance
  expense_account: Expenses:Unknown
  income_account: Income:Unknown
  currency: CNY

tabular_options: { delimiter: ",", flexible: true, encoding: auto }
skip_header_lines: 23
has_header_row: true
rules: []
```

```yaml
# mapping/third_party/alipay.yml（最小必填 4 列）
date: "交易时间"
payee: "交易对方"
narration: "商品"
amount: { column: "金额(元)", transform: abs }
```

### 场景 B：证券

在 A 的基础上增加：

```yaml
securities_accounts:
  cash_account: Assets:Broker:Galaxy:Cash
  fee_account: Expenses:Broker:Fee
  pnl_account: Income:Broker:PnL
  rounding_account: Expenses:Broker:Rounding
```

## 3. 写规则：分层优先

不要每条消费 × 每种支付方式写一条规则。用**两层**：

```yaml
# Layer 1: 付款方式 → 贷方 (priority 100)
- name: "付款-余额"
  conditions: [{ field: method, contains: 余额 }]
  action:
    credit_account: Assets:Wallet:Balance
  priority: 100

# Layer 2: 消费类别 → 借方 (priority 10-20)
- name: "消费-餐饮"
  conditions: [{ field: category, equals: 餐饮美食 }]
  action:
    debit_account: Expenses:Food
  priority: 10
```

Layer 2 不必写 `credit_account`——由 Layer 1 合并提供。N + M 条替代 N×M 条。

## 4. 规则调试策略

- 新规则从高 priority 开始，确认正确后调低
- 用 `terminal: true` 精确拦截特殊交易，防止被后续规则污染
- 用 `--log-level debug` 看每条规则命中情况
- 用 `--strict` 保证坏行直接报错而不是静默跳过

## 5. 推荐上线三步

1. 复制 `examples/<category>/<provider>/basic.yml` → 改成自己的账户名
2. 导入一条测试数据：`-p icbc -s testsets/icbc.csv -c config/icbc.yml --log-level info`
3. 看到正确 `.bean` 输出后，逐步加规则覆盖误判（看日志中 `success / ignored / failed` 比例）

## 6. 月度批量导入

```yaml
# batch-2026-06.yml
imports:
  - provider: icbc
    source: ~/Downloads/icbc-202606.csv
    output: src/transactions/2026/06/icbc.bean
  - provider: alipay
    source: ~/Downloads/alipay-202606.csv
    output: src/transactions/2026/06/alipay.bean
  # ... 逐个列出当月所有 provider
```

```bash
beancount-importer-rust --batch batch-2026-06.yml
```

所有相对路径基于 batch 文件所在目录解析。

## 7. 发布前检查清单

- [ ] mapping: 日期/金额/交易对方/摘要至少 4 列正确映射
- [ ] provider.yml: 账户名与账本一致（无 typo）
- [ ] 规则：能区分收入/支出，按类别区分消费桶
- [ ] 忽略类：第三方支付已单独导入的 via-bank 支付被忽略
- [ ] 测试数据集 CSV 放到 `testsets/`
- [ ] `examples/<category>/<provider>/` 同步更新 basic + advanced
- [ ] `cargo test --quiet` 通过
- [ ] 至少测试 3 条真实记录的导入输出

## 8. 团队维护建议

- 规则 PR 附"命中前后对比样例"（至少 3 条）
- 新增 provider 必须同时提交 testsets 测试集和 examples 示例
- 字段名变更先更新 mapping，再更新规则中引用的字段名
